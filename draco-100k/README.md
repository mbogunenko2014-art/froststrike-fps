# DRACO 100K — процедурный 3D-дракон

Один самодостаточный HTML-файл: `index.html`. Без библиотек, без сборки, без сервера, без интернет-зависимостей.

## Честные цифры (реально посчитанные сборщиком геометрии, не «на глаз»)

- **125 340 треугольников** (обещано ≥ 100 000 — перевыполнено)
- **64 384 уникальных вершин** — геометрия индексированная (32-битные индексы)
- **17 деталей** модели, каждая собирается отдельно с прогрессом в загрузчике
- Модель полностью процедурная: ни одного загруженного файла, всё генерируется кодом при запуске (детерминированно — seeded генератор, дракон всегда один и тот же)

## Дракон в деталях

Корпус с рёбрами и брюшными пластинами, шея, голова (череп с деформацией: надбровные дуги, скулы, ноздри), нижняя челюсть (открыта), 4 изогнутых рога + 2 малых, 36 зубов (верх и низ, с клыками), 2 глаза с янтарной радужкой и вертикальным зрачком (в шейдере), 4 ноги с мускулами и когтями, 2 перепончатых крыла на костяных лучах (плечевая + предплечье + палец), хвостовой плавник, гребень из 20 шипов вдоль спины, каменный постамент.

## Управление

- **Мышь**: вращение перетаскиванием, колесо — зум
- **Тач**: один палец — вращение, два пальца (щипок) — зум
- **Клавиши**: стрелки — orbit, `+`/`−` — зум
- Кнопки: автоповорот · каркас (wireframe) · 4 световых пресета (Солнце слева / Прожектор сзади / Полночь / Рассвет) · скриншот PNG · сброс камеры

## Рендер

- «Чистый» raw WebGL1 (не Three.js, не структуры — только API браузера)
- Требования: WebGL + расширение `OES_element_index_uint` (нужны для 32-битных индексов; при их отсутствии показывается честная панель, а не чёрный экран)
- Все материалы рисуются одним шейдером с выбором материала по uniform: чешуя с гекс-паттерном и бликами золота, костяная текстура рогов/когтей, слоновая кость зубов, глаз с энергией, жилы на перепонке крыльев, камень постамента
- 3 источника света: тёплый ключевой (вращается), холодная заливка, контровой rim; Blinn-спекуляр, AO по наклону, фреснель, тонмаппинг
- Режим каркаса строится лениво (дедупликация рёбер) при первом включении
- Статистика в реальном времени: треугольники, вершины, детали, FPS

## Честность запуска

- Прогресс-бар загрузки с названием каждой детали («деталь: череп», «деталь: перепонка крыла»…)
- Если нет WebGL — отдельная честная панель (не чёрный экран)
- Сторож-скрипт в отдельном блоке: если основной скрипт упал на старте, через несколько секунд появляется красная плашка с текстом ошибки (урок проекта GEKTAR: чёрный экран без объяснений — недопустим)
- Коллектор ошибок пишет всё во внутренний буфер для диагностики

## Ограничения (честно)

- Это процедурный арт: ультра-реалистичность здесь достигается плотностью геометрии (125k треугольников) и детализацией шейдера (чешуя/морщины/прожилки), а не фототекстурами — настоящие фотосканы драконов в одном HTML-файле физически невозможно уместить.
- В реальном браузере не тестировался (в окружении нет Chrome); автоматические проверки прогнали только логику, геометрию и запасные пути. GPU-путь (шейдеры, OES_element_index_uint) падает с честным сообщением.
- Загрузка и каркас на слабых машинах могут ощутимо считать несколько секунд — геометрия честно большая.

## Запуск

Скачайте `index.html` и откройте двойным кликом в Chrome/Firefox/Edge/Safari. Страница на GitHub — просто текст, скачанный файл ≠ превью на GitHub.

## Проверки

Автосмок (JSDOM, 28/28 PASS): честный путь без WebGL, панель glfail, пустой коллектор ошибок, 17 деталей, сухая сборка геометрии: 125 340 треугольников, все координаты числовые, разумные габариты (высота, длина тела, размах крыльев), корпус >30k, перепонки >8k, череп 12 288, зубы+рога на месте, 5 кнопок в DOM, клики без WebGL не падают, стрелки вращают камеру, сторож показывает плашку при упавшем скрипте. Синтаксис: `node --check` на всех 4 блоках — ОК; ровно 4 `<script>`-блока.
